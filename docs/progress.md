## 2026-09-11 — Checkpoint 1C: correctness fixes after review of 630de50

The project owner reviewed the checkpoint 1A/1B commit and found several issues in the training
and evaluation code. All findings were confirmed by inspecting the saved artefacts; none were
"already fine".

**Confirmed and fixed**

1. **The fine-tuning phase never ran.** `fit(initial_epoch=15, epochs=3)` is a no-op because Keras
   treats `epochs` as an absolute end epoch. The artefact history had 15 entries and the raw log
   stopped at `Epoch 15/15`. Now `initial_epoch=head_epochs, epochs=head_epochs + n`, and the
   script refuses to continue unless the phase really ran: it records `fine_tune_epochs_run`,
   `fine_tune_optimizer_steps` (162 this run) and a **post-unfreeze** `fine_tune_weight_delta`
   (4.8e-4), raising if nothing moved. My first 1C draft snapshotted the weights before unfreezing,
   so that check was itself meaningless until corrected.
2. **`final_val_accuracy` was read from `history["accuracy"]`** — it duplicated training accuracy.
   Fixed, and per-phase counts are recorded.
3. **Preprocessing was three different implementations** (training antialiased, evaluation not,
   Dart area-average). Evaluation now matches training, and `docs/preprocessing_spec.md` states the
   single spec. Augmentation also moved to explicit `value_range=(0, 255)` **before** rescaling,
   and the range assertion now runs after augmentation — in the first draft it still ran before, so
   it proved nothing about what the model received. That mistake was caught by the assertion firing
   on `1.05` vs `255.0`.
4. **Test scope was overstated.** The old cross-language test let INT8 disagree on the class. Now
   three separate checks: preprocessing conformance (image→tensor), runtime conformance (tensor→
   whole output vector, host **and Android**), and quantisation impact (FP32 vs INT8 accuracy).
   Tolerances come from the measured quantisation step (1/64 and 1.5/64 → bound 1/32).
5. **The recorded reference vector was contaminated.** Passing a numpy slice view to `set_tensor`
   produced a vector that disagreed with both Keras and the Dart runtime by 0.237. Inputs are now
   `np.ascontiguousarray`, and `tools/export_reference_fixture.py` builds every fixture from one
   canonical tensor and refuses to write if the float conversion disagrees with Keras (>5e-3).
6. **INT8 calibration used ≤16 augmented images.** Now 200 images in class order, augmentation off,
   photo ids recorded in `model_report.json`.
7. **The data freeze was not enforced.** `make_split.py` now refuses to overwrite a frozen protocol
   (tested: exit 4) and `verify_split.py` recomputes every image's content hash (tested: a one-byte
   same-size edit was detected) and cross-checks the split CSVs against `split.json`.
8. **Reproducibility for the marker.** `data/provenance_shareable.csv` (1,199 rows, location and
   local paths removed) plus the committed INT8 model and label file, so the app and tests run from
   a clone without retraining.

**Effect on results (same data set)**: best validation top-1 0.3006 → **0.411**; exported float
0.245/0.528 → **0.411/0.650**; INT8 0.153/0.448 → **0.252/0.534**. The improvement came from
enabling the phase that was supposed to run, not from more data — so "the model is weak" was
partly a wrong diagnosis until now.

**Verified after the fixes**: `flutter analyze` clean; 43 deterministic tests pass; 2 host
integration tests pass; the Android on-device runtime-conformance test passes on the emulator.
M1 accuracy targets remain unmet and unclaimed; the test split is still sealed.

## 2026-09-11 — Checkpoint 1D: gaps closed, one controlled data experiment

**Three verification gaps closed.** Details and evidence: `docs/checkpoint_1d_report.md`.

1. **Preprocessing evidence.** Synthetic asymmetric fixtures plus per-channel region assertions
   replace statistics-only checks, and all eight EXIF orientations are covered. Two meta-tests prove
   the assertions can fail. This found two real defects: the `image` package decoders never populate
   EXIF (so `bakeOrientation` did nothing), and its orientation-6 branch rotates the wrong way
   relative to the spec. The app now parses orientation itself (`lib/services/exif_orientation.dart`)
   and the transform table is verified against Pillow for all eight values.
2. **Evaluation script.** The strict Keras check now applies to the FP32 conversion only; the INT8
   difference is recorded as quantisation cost. A missing checkpoint is reported as `not-run`
   instead of a fabricated zero reference. Results carry run id, data version and model hashes, and
   are written only after the checks pass.
3. **Clone reproducibility.** The fixture the preprocessing test reads is no longer git-ignored;
   runtime conformance is split into a committed-assets scope and a research scope that skips with a
   reason; `tools/run_checks.py` reports skips separately. Verified by cloning to a new directory
   and running the README commands: analyze clean, 41 deterministic + 6 host-integration passed,
   1 skipped (float model), 2 on-device passed.
